# 怎麼補作品頁的資料

每個作品的頁面 `/work/<專案名>/` 由上到下有這些區塊：

1. 主視覺：圖示、名稱、標語、說明、按鈕，右邊一張畫面
2. 怎麼用：步驟卡，加一張重點卡
3. 功能分組
4. 看看畫面
5. 所有功能
6. 常見問題、相關教學、最近更新
7. 結尾卡

**有寫資料的區塊才會出現。** 什麼都沒寫的專案只有主視覺、最近更新和同類作品，頁面一樣成立。

資料放在這個資料夾，**檔名跟 GitHub 的 repo 名稱一樣**（大小寫不用管）：

```
content/SpeakSlow.json    → /work/SpeakSlow/ 的各個區塊
content/SpeakSlow.md      → 同一頁裡的長篇文章（可有可無，寫法見 _怎麼寫文章.md）
```

現成的範例是 `SpeakSlow.json`，複製一份改名最快。

## 欄位

每個欄位都可以省略。

```json
{
  "tagline": "名稱下面那句紅色的標語",
  "note": "價格、平台之類的一行備註",

  "cta": [
    { "label": "下載 Windows 版", "url": "https://…" }
  ],

  "steps": [
    { "title": "第一步的標題", "text": "一句說明" }
  ],
  "highlightsTitle": "重點卡的小標（預設是「重點」）",
  "highlights": ["一句重點", "再一句"],

  "groups": {
    "label": "標題上面的小字",
    "title": "這一區的標題",
    "intro": "第一張帶底色的卡片上的引言",
    "items": [
      { "title": "分類名稱", "text": "這一類有什麼" }
    ]
  },

  "screens": [
    { "src": "img/檔名.jpg", "alt": "這張畫面在講什麼" }
  ],

  "features": [
    { "title": "功能名稱", "text": "一句說明" }
  ],

  "faq": [
    { "q": "問題", "a": "回答" }
  ],

  "guides": ["教學的檔名（不含 .md）"]
}
```

## 各欄位的行為

- **`cta`**：第一個是主要按鈕（墨色實心），其餘是次要。網址要以 `http://` 或 `https://` 開頭。「看原始碼」和「官方介紹頁」會自動接在後面，不用自己寫。
- **`steps`**：建議三步。卡片上的 01、02、03 是自動編的。
- **`highlights`**：有寫才會出現那張墨色的重點卡，放在步驟卡的右邊。
- **`groups`**：一定要有 `title` 才會出現。
- **`screens`**：圖放在 `content/img/`，這裡寫 `img/檔名`。第一張放在主視覺的右邊；有兩張以上，才會另外出現「看看畫面」把全部排出來。沒寫這一欄的話，會用 `src/img/shots/<專案名>` 那一張。
- **`faq`**：第一題預設展開。回答是純文字，不能放連結或換行。
- **`guides`**：填 `guides/` 資料夾裡的檔名。對不上的會自動略過。

## 注意

- 這是 JSON，最後一項後面不能有逗號，字串要用雙引號。寫壞了 build 時會印警告並略過那個檔，網站不會壞。
- 截圖寬度建議 1000 以上。現在 SpeakSlow 那兩張只有 600 左右，在高解析螢幕上會偏軟。
- 底線開頭的檔案（像這一份）不會被當成資料。
